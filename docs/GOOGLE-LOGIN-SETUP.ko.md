# Google 로그인 및 인스타 이미지 패치

이번 ZIP에는 직전에 제공한 복구본에서 **수정·추가한 파일만** 들어 있습니다. 폴더 구조 그대로 기존 저장소의 같은 경로에 반영하세요. 삭제할 파일은 없습니다. 기존 파일과 병합하거나 내용을 덧붙이지 말고, ZIP에 포함된 파일을 같은 경로에 교체하면 됩니다.

## 인스타 이미지

글 상세 화면의 인스타 이미지 만들기 영역에서 크기와 **이미지 스타일**을 고릅니다.

- 기본: 흰 배경의 단정한 이미지.
- 레트로 초록: 검은 배경, 초록 글씨와 터미널 테두리.
- 픽셀 농장: 나무 프레임, 살구색 패널과 픽셀 새싹 장식.

처음에는 현재 블로그 UI를 따릅니다. 이미지 스타일을 따로 선택하면 블로그 UI와 독립적으로 바꿀 수 있습니다. 표지·본문·사진에 선택한 스타일이 적용되고, 정사각형과 세로형을 지원합니다. 이미지 미리보기에서 한 장씩 받거나 전체 다운로드할 수 있습니다.

## 기존 운영자 계정은 어떻게 하나요?

**기존 이메일을 바꾸거나 운영자 계정을 새로 만들 필요가 없습니다.** 아래 Google 설정과 DB 업그레이드를 끝낸 뒤:

1. 로그인 화면에서 **기존 계정으로 로그인**을 펼칩니다.
2. 원래 운영자 이메일·비밀번호로 로그인합니다.
3. **내 정보 → Google 로그인 → Google 계정 연결**에서 기존 비밀번호를 다시 입력합니다.
4. 앞으로 로그인에 사용할 Google 계정을 선택합니다. Google 이메일은 기존 운영자 이메일과 달라도 됩니다.
5. 연결 완료 안내를 확인한 뒤 로그아웃하고 **Google로 계속하기**로 로그인해 봅니다.

같은 회원 ID에 로그인 수단을 추가하므로 관리자 권한·작성 글·생일·블로그 이메일·뉴스레터 설정이 유지됩니다. 뉴스레터 수신 주소도 원래 블로그 이메일을 사용합니다.

운영자는 **Google로 새 가입하기 전에 위 연결부터** 진행하세요. Google로 먼저 신규 가입하면 별도의 독자 계정이 만들어질 수 있습니다. 이미 다른 블로그 계정에 연결된 Google 계정을 자동으로 빼앗거나 계정을 합치지는 않습니다.

이메일 주소가 같은 기존 회원도 자동 병합하지 않습니다. 기존 비밀번호로 로그인한 후 연결해야 합니다. Gmail 주소가 없는 Google 계정도 연결할 수 있습니다.

## 1. 기존 DB에 추가 스키마 적용

`prisma/upgrade-google-login.sql`을 기존 PostgreSQL의 SQL 실행 화면에서 실행하거나, 환경 변수가 설정된 로컬 프로젝트에서 아래 명령을 실행하세요.

```bash
npm install
npm run db:upgrade:google
npm run db:generate
```

추가되는 것은 Google 계정 식별자·연결 이메일과 10분짜리 일회성 인증 흐름 저장소입니다. 기존 회원·글을 지우거나 권한을 바꾸는 SQL은 없습니다. 데이터베이스 초기화나 데이터 삭제 명령은 실행하지 마세요.

DB 업그레이드는 Google 관련 코드로 배포하기 전에 완료해야 합니다. 기존 데이터베이스 연결 변수는 `thinkstorage_DATABASE_URL`입니다. `prisma/schema.prisma`, `package.json`도 패치에 포함된 새 파일로 함께 반영하세요.

## 2. Google OAuth 클라이언트 생성

Google Cloud Console의 **Google Auth Platform**에서 프로젝트를 선택하거나 만듭니다. 앱 이름·지원 이메일 등 기본 정보를 등록하고, 일반 독자도 가입할 사이트라면 외부 사용자용으로 설정합니다. 배포 상태와 테스트 정책은 콘솔의 현재 안내를 따르세요.

**클라이언트 → 클라이언트 만들기 → 웹 애플리케이션**을 선택합니다. 승인된 리디렉션 URI에는 실제 고정 블로그 주소로 아래 주소를 정확히 추가합니다.

```text
https://실제-블로그-주소/api/auth/google/callback
```

현재 사용 중인 고정 Vercel 주소가 `https://my-blog.vercel.app`이면:

```text
https://my-blog.vercel.app/api/auth/google/callback
```

경로·슬래시까지 정확히 맞아야 합니다. 와일드카드나 매번 달라지는 프리뷰 주소를 사용하지 마세요. OAuth 클라이언트의 ID와 비밀번호를 발급받습니다. 이 앱은 `openid email profile`만 요청합니다.

## 3. Vercel 환경 변수 등록 후 배포

Vercel 프로젝트 설정의 환경 변수에 아래 값을 등록합니다.

| 이름 | 값 |
| --- | --- |
| `GOOGLE_CLIENT_ID` | 발급받은 OAuth 클라이언트 ID |
| `GOOGLE_CLIENT_SECRET` | 발급받은 OAuth 클라이언트 비밀번호 |
| `SITE_URL` | 실제 고정 블로그 주소. 예: `https://my-blog.vercel.app` |

비밀값은 GitHub에 올리거나 채팅에 붙여넣을 필요가 없습니다. `NEXT_PUBLIC_` 접두사도 붙이지 않습니다. 기존 `ADMIN_EMAIL`은 그대로 두어도 됩니다. Google 로그인은 이 환경 변수와 이메일만 보고 관리자 권한을 부여하지 않습니다.

환경 변수와 패치 파일을 반영하고 재배포합니다. 이후 위의 운영자 연결 절차를 진행하세요. Google 설정 전에도 기존 회원의 비밀번호 로그인은 남아 있습니다.

## 동작과 검증 범위

- 신규 가입은 Google로 진행하며 항상 독자 권한으로 시작합니다. 뉴스레터 구독은 별도 선택입니다. 생일은 내 정보에서 등록합니다.
- 기존 비밀번호 로그인은 기존 계정의 연결·복구용으로 유지합니다. `/register`는 로그인 화면으로 연결되고, 비밀번호 신규 가입 API는 Google 가입을 안내합니다.
- Google 계정은 검증된 `sub`로 식별합니다. JWT 검증은 `jose`를 사용하고, 서명·발급자·대상·유효기간·nonce·검증된 이메일을 확인합니다.
- 일회성 상태 값과 브라우저 쿠키, PKCE를 사용합니다. 기존 계정 연결은 비밀번호 재확인 후 시작하며 콜백에서도 같은 회원·세션인지 확인합니다.
- 기존 테스트와 계정 연결 정책 테스트 40개 통과. 인스타 PNG 6종의 Canvas 렌더링과 관련 컴포넌트 타입 검사를 통과했습니다. 실제 백엔드 코드를 사용한 인증 흐름 모의 실행 14개 시나리오 그룹도 통과했습니다.
- 작업 환경의 패키지 다운로드 제한으로 새 `jose` 의존성을 실행하는 서명 검증 테스트와 전체 Next.js 빌드는 실행하지 못했습니다. 실제 Google 인증과 운영 DB 마이그레이션도 설정 후 확인해야 합니다.

## 오류가 나면

- `redirect_uri_mismatch`: Google에 등록한 콜백과 `SITE_URL`의 주소·경로가 정확히 같은지 확인합니다.
- 로그인 요청 만료: 원래 브라우저에서 Google로 계속하기를 다시 누릅니다. 여러 창에서 동시에 연결을 시작하면 이전 요청이 무효가 될 수 있습니다.
- 이미 가입된 이메일: 기존 이메일·비밀번호로 로그인해 내 정보에서 Google를 연결합니다.
- 다른 회원에게 연결된 Google 계정: 다른 Google 계정을 선택합니다. 자동 계정 병합은 하지 않습니다.
- Google 로그인이 준비 중: 환경 변수 등록과 재배포를 확인합니다.
