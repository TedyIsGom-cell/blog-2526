# 20년대식 — 함께 쓰는 블로그

기존 Next.js·PostgreSQL 블로그에 회원·직책·주간 뉴스레터·이메일 투고를 추가한 수정본입니다. 기존 글·댓글·카테고리·사진·검색·다크 모드 기능을 유지합니다. 공개 글은 로그인하지 않아도 읽을 수 있습니다.

## 회원 권한

| 기능 | 독자 | 집필자 | 관리자 |
| --- | --- | --- | --- |
| 공개 글 읽기·뉴스레터 신청 | 가능 | 가능 | 가능 |
| 새 글 발행·사진 첨부 | — | 가능 | 가능 |
| 본인 글 수정 | — | 가능 | 가능 |
| 다른 사람의 글 수정 | — | — | 가능 |
| 글 삭제 | — | — | 가능 |
| 직책·카테고리·댓글 관리 | — | — | 가능 |
| 이메일 투고 | — | 본인 전용 주소 | 본인 전용 주소 |

신규 가입자는 독자입니다. 관리자는 대시보드의 회원 목록에서 집필자·관리자를 지정합니다. 마지막 관리자 계정은 독자로 변경할 수 없습니다. 직책은 화면뿐 아니라 서버에서도 확인합니다.

## 생일과 작성 당시 일수

- 회원가입 시 생일을 선택 입력하고 `/account`에서 추가·수정·삭제할 수 있습니다.
- 모든 글·회원 댓글·답글은 각 작성자의 생일과 **작성 당시 한국 날짜**를 기준으로 계산해 날짜 옆에 `(7305 일)` 형태로 표시합니다. 태어난 날을 1일로 셉니다.
- 생일을 변경하면 기존 글과 계정에 연결된 댓글도 다시 계산합니다. 생일이 없거나 작성자 연결이 없는 과거 글·비회원 댓글은 `(생일 미등록)`을 표시합니다. 이름이 같은 사람의 생일을 임의로 연결하지 않습니다.
- 로그인한 회원의 댓글은 본인 계정으로 기록합니다. 비회원 댓글도 유지합니다.
- 기본 제목을 개인 이름에서 **20년대식**로 바꿨습니다.

이미 이전 회원·뉴스레터 수정본을 적용했다면 새 코드를 올리기 전에 `npm run db:upgrade:birthday`로 추가 컬럼을 적용하세요. 처음 적용하는 기존 블로그는 `npm run db:upgrade`가 회원 기능과 생일 기능을 순서대로 적용합니다.

## 추가한 기능

- `/register`, `/login`, `/account`: 이메일·비밀번호 회원가입과 로그인, 내 계정.
- `/admin/dashboard`: 전체 글·회원·뉴스레터·카테고리 관리. 집필자에게는 본인 글 관리만 표시.
- 뉴스레터: 본인 이메일 확인 후 구독. 여러 작성자의 아직 소개되지 않은 공개 글을 제목·작성자·요약·원문 링크로 묶어 주간 발송.
- 이메일 투고: 집필자별 전용 주소를 생성. 등록한 이메일에서 보낸 인증된 메일의 제목·일반 텍스트 본문을 자동 게시.
- 로그아웃 시 서버 세션 폐기, 비밀번호 scrypt 저장, 로그인 시도 제한, 투고 서명 확인·중복 방지.

## 적용 순서

**상세한 설명은 [운영 설정 안내](docs/OPERATIONS.ko.md)에 있습니다. 기존 운영 DB가 있다면 먼저 백업하세요.**

1. Node.js 20.9 이상에서 `npm install`.
2. `.env.example`을 `.env`로 복사하고 DB·관리자 환경변수 입력. 같은 값을 배포 환경에도 설정.
3. 기존 블로그 DB: `npm run db:upgrade`. 완전히 새 DB: `npm run db:init`. 두 명령 중 해당하는 하나만 실행.
4. `npm run db:generate`, `npm run typecheck`, `npm test`, `npm run build` 실행 후 기존 Vercel 프로젝트에 배포.
5. `/register`에서 `ADMIN_EMAIL`과 일치하는 주소·초기 설정 키로 최초 관리자 가입. 다른 회원에게 집필자 직책 부여.
6. 기존 글을 관리자 이름으로 표시하려면 `npm run db:claim-legacy` 실행.
7. Resend의 발신 주소·API 키와 정기 실행을 설정하면 뉴스레터가 동작. 수신 도메인·웹훅까지 설정하면 이메일 투고도 동작.

기존 `ADMIN_PASSWORD`·`ADMIN_SECRET` 로그인은 사용하지 않습니다. 최초 관리자 계정 생성 후 `ADMIN_SETUP_TOKEN`은 배포 환경에서 제거할 수 있습니다.

## 정기 발송 기본값

`vercel.json`은 매일 UTC 00:00(한국 09시경)에 실행합니다. 뉴스레터는 **한국 월요일 09시를 기준으로 주당 한 묶음만** 생성합니다. 정상 운영 시 월요일 아침 새 묶음이 만들어지고, 미처리 수신자는 이후 실행 때 이어서 보냅니다. 새 글이나 확인된 구독자가 없으면 만들지 않습니다. 관리자가 먼저 수동 발송하면 그 주의 자동 발송은 같은 묶음을 이어서 처리합니다.

한 묶음에 최대 30편, 한 번의 실행에 최대 40명까지 처리합니다. 이보다 많은 글은 다음 주, 아직 시도하지 않은 수신자는 다음 실행에서 처리합니다. 수신자가 많거나 빠른 재시도가 필요하면 별도 시간별 실행을 설정합니다. `vercel.pro.example.json`은 시간별 설정 예시입니다. Hobby에서 시간별 Cron 설정은 배포에 실패하므로 기본값은 일별입니다.

## 검증 상태

이 수정본을 작성한 환경에서 패키지 서버 접근이 HTTP 403으로 차단되었습니다. 따라서 `npm install`, Prisma 클라이언트 생성, 운영 DB 업데이트, 전체 타입 검사·프로덕션 빌드·실제 메일 송수신은 검증하지 못했습니다. 제공 코드를 운영 환경에 연결하기 전 위 적용 순서의 검사를 실행해주세요.

환경에 있던 TypeScript·React 도구로 인증·권한·메일 서명·콘텐츠 URL·뉴스레터 구성 단위 테스트 33개와 권한별·생일 입력 화면의 가짜 데이터 기반 렌더링 검사는 통과했습니다. 테스트는 실제 데이터베이스·메일 제공자 연동을 대체하지 않습니다. 테스트 파일은 `tests/`에 있습니다.

## 구성

- Next.js 15.5.28, React 19, Prisma 5, PostgreSQL.
- 발신·수신: Resend HTTP API. 메일 기능의 비밀값은 서버 환경변수에만 저장.
- `prisma/schema.prisma`: 전체 데이터 모델.
- `prisma/upgrade-collaboration.sql`: 기존 DB 보존용 추가 테이블·컬럼 SQL.
- `docs/OPERATIONS.ko.md`: 관리자·메일·정기 실행 설정과 운영 제한.
